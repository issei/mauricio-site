Deterministic Grounding for Software Agentic Engineering

How to anchor context, constrain actions, and validate changes without confusing a green test with global correctness.

An agent can produce syntactically correct code, pass available unit tests, and yet violate architecture, scope, privacy, or the repository's current state.

Agent Premises (A_t)

Prompt: "Add PDF Export Route"
Retrieved Context: RAG Index (Commit C1)
Hypothesis: 'pdf-kit' v1.2 dep present
Plan: Modify src/api/export.js and package.json

Observable Repository State (S_t)

Snapshot: Commit C2 (HEAD)
Lockfile: pdf-kit removed in C2
Policy: src/api/ restricted by ADR-014
Real Diff: Change in C1 conflicts with C2

Agent–Repository Gap: G_t = Premises(A_t) − Verified_predicates(S_t) ≠ 0

"Correct code in isolation can still be the wrong change."
