# Mauricio Site — Coding Patterns

## Commit Conventions

This project uses a **mixed commit style** — informal PT-BR messages for quick changes, and English `feat:` prefix for significant new pages or features.

| Pattern | Examples |
|---|---|
| `feat:` prefix | `feat: Add new page detailing DevOps Salesforce...` |
| PT-BR informal | `ajuste cv`, `melhorias`, `adicionado audio`, `restruturação` |
| "Versão atualizada" | Used for multi-file update batches |
| Merge commits | Auto-generated by GitHub PRs with AI-suggested branch names |

**Rule of thumb**: Use `feat:` for new `.html` pages. Use short PT-BR for data/content-only changes (`cv.json`, assets).

## Code Architecture

This is a **Multi-Page Application (MPA)** built with Vite 6, Tailwind CSS v4, and vanilla JavaScript ES6 modules. Each page is a standalone `.html` file.

```
mauricio-site/
├── src/                       # Vite root — all HTML pages live here
│   ├── index.html             # Landing page (CV dinâmico)
│   ├── *.html                 # One file per page/proposal/content area
│   ├── js/
│   │   ├── cv-renderer.js     # CV dynamic rendering engine
│   │   ├── github-service.js  # GitHub API client
│   │   └── admin-ui.js        # Admin panel logic
│   ├── config.js              # GitHub credentials & URLs
│   ├── input.css              # Tailwind v4 entry point
│   └── style.css              # Custom overrides / one-off animations
│
├── public/                    # Static assets (not processed by Vite)
│   ├── cv.json                # Local fallback for CV data
│   ├── robots.txt, favicon.svg, site.webmanifest
│   └── fotos/, *.pdf, *.m4a  # Media assets
│
├── docs/specs/                # Specification-Driven Development docs
│   ├── ARCHITECTURE.md
│   ├── STYLE_GUIDE.md
│   ├── TESTING_GUIDE.md
│   ├── CV_SYSTEM.md
│   └── ...
│
├── tests/                     # Playwright test files (*.spec.js)
├── e2e/                       # Additional E2E specs
├── .agents/                   # AI agent configuration
│   ├── skills/                # Skill modules (this file lives here)
│   ├── commands/              # Slash commands
│   ├── agents/                # Agent definitions
│   └── workflows/             # Workflow definitions
│
├── vite.config.js             # Auto-discovers all src/*.html as entry points
├── playwright.config.js
└── package.json
```

### Key Architecture Decisions

- **MPA, not SPA**: Every feature is a separate `.html` file in `src/`. No routing framework.
- **Vite auto-discovers all HTML**: `vite.config.js` uses `globSync('src/*.html')` — adding a new page requires no config change.
- **Tailwind CSS v4**: Uses `@import` syntax in `input.css`. No `tailwind.config.js`.
- **GitHub as CMS**: `cv.json` is fetched from `raw.githubusercontent.com` at runtime; local `public/cv.json` is the fallback.
- **ES6 native modules**: `<script type="module">` everywhere — no transpilation to ES5.

## Workflow: Adding a New Page

The most common operation in this repo (13 commits on `devops-salesforce.html` alone). Follow this pattern:

1. **Create `src/<page-name>.html`**
   - Copy an existing complex page (e.g., `service-operations-2-0.html`) as a design reference.
   - Must include: `<title>`, `<meta name="description">`, Google Fonts (Inter), Font Awesome, Tailwind CSS v4.

2. **Apply the Dark Tech design system** (see Design System section below).

3. **Vite picks it up automatically** — no `vite.config.js` changes needed.

4. **Add a test** in `tests/<page-name>.spec.js`:
   ```javascript
   import { test, expect } from '@playwright/test';
   test('deve carregar <page> com sucesso', async ({ page }) => {
     const response = await page.goto('/<page-name>.html');
     expect(response.status()).toBe(200);
   });
   ```

5. **Commit with `feat:` prefix**:
   ```
   feat: Add new page for <description>
   ```

## Workflow: Updating the CV

**Option A — Direct file edit** (most common, e.g., `ajuste cv` commit):
```
1. Edit public/cv.json
2. git commit -m "ajuste cv"
3. Push to main → GitHub Actions deploys automatically
```

**Option B — Via admin panel** (`/admin.html`):
```
1. Authenticate with GitHub token
2. Edit via UI
3. Save → GitHub API → auto-commit to issei/curriculo repo
```

The CV `cv.json` schema (TypeScript-style) is documented in `docs/specs/CV_SYSTEM.md`. Key top-level fields:
- `Nome`, `Titulo`, `ResumoHero`, `Resumo[]`
- `Habilidades: { [categoria]: string[] }`
- `Experiencia[]`, `Projetos[]` (STAR format), `Formacao_Academica[]`
- `Certificados[]`, `Cursos_Alura: { [categoria]: string[] }`
- `Recomendacoes_Recebidas[]`, `Contato`

## Design System: "Dark Tech & Developer Centric"

All pages must follow these rules (from `docs/specs/STYLE_GUIDE.md`):

### Color Palette

| Role | Value | Usage |
|---|---|---|
| Background | `#0d1117` | `body` background (GitHub Dark Dimmed) |
| Secondary BG | `#161b22` | Cards, modals, footer |
| Primary text | `#c9d1d9` | Body copy |
| Headings | `#ffffff` | `h1`, `h2`, `h3` |
| Accent Blue | `#007bff` | Buttons, links, highlights |
| Accent Purple | `#8a2be2` | Gradient secondary color |
| Gradient | `linear-gradient(90deg, #007bff, #8a2be2)` | CTA buttons, section underlines |

### Typography

- **Font**: `Inter` from Google Fonts (weights: 300, 400, 600, 700, 800)
- `h1`: `text-5xl md:text-7xl font-extrabold`
- `h2`: `text-4xl font-bold` with `.section-title` gradient underline
- `body`: `text-lg text-gray-300 leading-relaxed`

### Key CSS Patterns

```css
/* Section title with neon underline */
.section-title::after {
    background: linear-gradient(90deg, #007bff, #8a2be2);
    box-shadow: 0 0 10px rgba(0, 123, 255, 0.5);
}

/* Cards with hover elevation */
.project-card:hover {
    transform: translateY(-5px);
}

/* Glassmorphism navbar */
nav { backdrop-filter: blur(8px); }

/* Hero pulsating background */
/* radial-gradient(rgba(0, 123, 255, 0.1)) */
```

### Hard Rules

1. **Never use light backgrounds** — always dark (`#0d1117`, `#161b22`)
2. **Always use Inter** — never browser defaults
3. **Preserve glow effects** — colored box-shadows on interactive elements
4. **High contrast** — light text on dark backgrounds only

## JavaScript Patterns

### ES6 Module Imports

```html
<!-- index.html pattern -->
<script type="module">
  import { initCVRenderer } from './js/cv-renderer.js';
  initCVRenderer('./cv.json');
</script>

<!-- admin.html pattern -->
<script type="module">
  import { GitHubService } from './js/github-service.js';
  import { GITHUB_CONFIG } from './config.js';
</script>
```

### State Management

State is kept in **module-level closures** — no global state object, no external store:
- `cv-renderer.js`: `profileData` held in closure
- `admin-ui.js`: `currentData` and `fileSha` held in closure
- Cross-module communication via **DOM events** when needed

### GitHub Service API

```javascript
const service = new GitHubService();
await service.validateToken(token);
const { content, sha } = await service.getFile(token, owner, repo, path);
await service.updateFile(token, owner, repo, path, content, sha, message);
```

## Testing Patterns

Framework: **Playwright** (cross-browser: Chromium, Firefox, WebKit). No unit test framework currently active — Vitest is documented but not yet in `package.json`.

Test files live in `tests/` and `e2e/`. Pattern: `tests/<feature>.spec.js`.

### Required Tests for Every New Page

```javascript
import { test, expect } from '@playwright/test';

// 1. Smoke test
test('deve carregar /nova-pagina.html com sucesso', async ({ page }) => {
  const response = await page.goto('/nova-pagina.html');
  expect(response.status()).toBe(200);
});

// 2. SEO check
test('deve ter title e meta description', async ({ page }) => {
  await page.goto('/nova-pagina.html');
  const title = await page.title();
  expect(title.length).toBeGreaterThan(10);
  expect(title.length).toBeLessThan(60);
  const desc = await page.getAttribute('meta[name="description"]', 'content');
  expect(desc?.length).toBeGreaterThan(50);
});
```

### Test Commands

```bash
npx playwright test                          # All tests
npx playwright test tests/home.spec.js       # Single file
npx playwright test --project=chromium       # Specific browser
npx playwright test --ui                     # Interactive UI mode
```

## CI/CD & Deploy

**Trigger**: Push to `main` branch  
**Pipeline**: GitHub Actions (`.github/workflows/deploy.yml`)

```
Push → npm install → npm run build → AWS OIDC auth → S3 sync → CloudFront invalidation
```

**Required GitHub Secrets**: `AWS_ROLE_ARN`, `AWS_REGION`, `S3_BUCKET_NAME`, `CLOUDFRONT_DISTRIBUTION_ID`

**Local dev**: `npm run dev` — starts Vite at `localhost:5173` (strictPort).

## SEO Checklist for Every HTML Page

Every page in `src/*.html` must have:

```html
<title>Descriptive Title (10-60 chars)</title>
<meta name="description" content="Compelling description (50-160 chars)">
<meta property="og:title" content="...">
<meta property="og:description" content="...">
<link rel="canonical" href="https://mauricio.issei.com.br/page-name.html">
```

The sitemap is auto-generated by `vite-plugin-sitemap` during build. No manual sitemap edits needed.

## Files Co-Changed Together (Patterns)

| When you change... | Also check/update... |
|---|---|
| A `src/*.html` page | `tests/<page>.spec.js` — add/update smoke test |
| `public/cv.json` | `src/cv.json` — keep in sync (local fallback) |
| `src/index.html` | `src/index.template.html` — parallel template |
| `vite.config.js` | `package.json` — dependency alignment |
| Any spec in `docs/specs/` | Corresponding implementation file |
| `.github/workflows/deploy.yml` | `.github/workflows/playwright.yml` |
